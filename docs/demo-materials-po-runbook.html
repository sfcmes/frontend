Demo Runbook — วัสดุ & สูตร → คำนวณวัสดุ → ใบสั่งซื้อ (PO)

คู่มือกดโชว์สดให้ user ดู 3 หน้า พร้อมลำดับกรอกข้อมูลที่ถูกต้อง และกับดักที่ทำให้ demo พัง

Project → Section → Component (พรีคาสท์ · status=planning · ปริมาตร>0) │ type ถูกตั้ง = "precast" อัตโนมัติ Materials (ทะเบียนวัสดุ) ─┤ Recipe (สูตร: ประเภท="precast", แหล่งค่า=ปริมาตร) → Admin เปิดใช้งาน ▼ คำนวณวัสดุ (เลือกโครงการ) → สร้าง PO ร่าง → จัดการ PO

! กับดัก 8 อย่างที่ทำให้ demo พัง — อ่านก่อน

ถ้าหน้าคำนวณขึ้น "ตารางว่าง" หรือ "แถบคำเตือนสีทอง" มักมาจากข้อใดข้อหนึ่งนี้
  1. ต้อง login เป็น Admin — buyer ไม่ถูก seed ในระบบ; การเปิดใช้งานสูตร = Admin เท่านั้น; action ของ PO/วัสดุ = buyer/Admin
  2. ใช้แท็บ "ชิ้นงานพรีคาสท์" เท่านั้น — "ชิ้นงานอื่นๆ" เก็บคนละตาราง (other_components) การคำนวณ มองไม่เห็น
  3. สถานะชิ้นงานต้องเป็น "รอผลิต" (planning) — สถานะอื่นไม่ถูกนับ
  4. ประเภทในสูตรต้องเป็น precast — พรีคาสท์ถูกตั้ง type = "precast" อัตโนมัติ (จับคู่ไม่สนตัวพิมพ์เล็ก-ใหญ่)
  5. แหล่งค่าในสูตรต้องตรงกับช่องที่กรอกค่าบวก — เลือก "ปริมาตร" ในสูตร ⇒ ชิ้นงานต้องมีปริมาตร > 0
  6. ต้องกด "เปิดใช้งาน" สูตร — สูตรสถานะ "ร่าง" ไม่ถูกนำมาคำนวณ
  7. ช่อง พื้นที่/ปริมาตร/น้ำหนัก ในฟอร์มพรีคาสท์ กรอกมือ (ฟอร์มนี้ไม่คำนวณให้) + ต้องแนบไฟล์ PDF
  8. หน่วยน้ำหนักในสูตรเขียน kg แต่ฟอร์มกรอกเป็น "ตัน" → แนะนำใช้ "ปริมาตร" ใน demo เพื่อเลี่ยงความสับสน

D ชุดข้อมูลตัวอย่างสำหรับ demo (กรอกตามได้เลย)

B สคริปต์ demo สด โชว์ให้ user ดู

B1 · หน้า "วัสดุและสูตร" /forms/form-materials

  • แท็บ ทะเบียนวัสดุ: คลังวัสดุที่สั่งซื้อได้
  • แท็บ สูตรวัสดุ: กติกาแปลงชิ้นงาน → วัสดุ ชี้สถานะ "ใช้งาน"
  • ปุ่ม ? มุมขวาบน = ทัวร์สอนในหน้าจริง กดโชว์ได้

B2 · หน้า "คำนวณวัสดุ" /forms/form-material-requirements — ไฮไลต์

  1. ติ๊กเลือกโครงการ SKV-101 → กด คำนวณความต้องการ
  2. ชี้ 2 แถว: คอนกรีต "ต้องสั่งเพิ่ม 4 ลบ.ม." · เหล็ก "400 กก." (คอลัมน์สีทอง = ยอดที่ยังขาด)
  3. กดที่แถวคอนกรีต เพื่อกางดูที่มา: W-01/02/03 × ตัวคูณ 1 × เผื่อเสีย 5% (ตรวจย้อนได้ทุกตัวเลข)
  4. ติ๊กทั้ง 2 วัสดุ → สร้างใบสั่งซื้อ (ร่าง) → ยืนยัน → ระบบสร้าง PO 2 ฉบับ (SCG · ทาทา สตีล) + ให้ลิงก์ไปหน้า PO

B3 · หน้า "ใบสั่งซื้อ (PO)" /forms/form-po

  • แท็บสถานะ: ร่าง → รอสั่งซื้อ → สั่งซื้อแล้ว → รับของแล้ว
  • เปิด PO ร่างที่เพิ่งสร้าง → แก้ไข / ส่งให้ผู้จัดซื้อ
  • โชว์ปุ่มที่เปลี่ยนตามสถานะ: ยืนยันสั่งซื้อ → ยืนยันรับของ
  • เมื่อรับของแล้ว ยอด "สั่งแล้ว/ค้างรับ" จะกลับไปหักใน B2 อัตโนมัติ (วงจรครบ)

? "ประเภทชิ้นงาน" ในสูตร เอามาจากไหน

ช่อง "ประเภทชิ้นงาน" ตอนสร้างสูตร เป็น ช่องพิมพ์ข้อความอิสระ — ค่าที่พิมพ์คือคอลัมน์ type ของชิ้นงาน ระบบเอาไปจับคู่แบบ ไม่สนตัวพิมพ์เล็ก-ใหญ่ (LOWER(recipe.component_type) = LOWER(component.type))

ค่า type ของชิ้นงานมาจาก 1 ใน 3 ทางนี้:

ชิ้นงานสร้างจากtype เป็นอะไรคำนวณเห็นไหม
ฟอร์ม พรีคาสท์ บังคับเป็น precast เสมอ (ฟอร์มไม่มีช่องให้เลือก) ✅ เห็น
นำเข้าด้วย Excel อ่านจากคอลัมน์ "ประเภทชิ้นงาน" ในไฟล์ → ตั้งเองได้ (เช่น เสาเข็ม, คาน) ✅ เห็น
ฟอร์ม ชิ้นงานอื่นๆ เก็บคนละตาราง (other_components) ❌ ไม่เห็น
สรุปสำหรับ demo
ถ้าสร้างชิ้นงานผ่านฟอร์ม พรีคาสท์ (วิธีที่แนะนำ) → ในสูตรต้องพิมพ์ precast เป๊ะๆ
ถ้าอยากได้ประเภทกำหนดเอง → นำเข้าผ่าน Excel กรอกคอลัมน์ "ประเภทชิ้นงาน" แล้วในสูตรพิมพ์ให้ตรงคำนั้น

✓ เช็คลิสต์แก้ปัญหา (ถ้าคำนวณไม่ออก)
