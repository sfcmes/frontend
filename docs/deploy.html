1Architecture

Two Lightsail instances. The browser only ever talks to the frontend box; the backend is reached through nginx over the internal private network, so backend port 3000 is never exposed to the internet.

Phone / Browser
     |  http://18.140.71.168/           (SPA, same-origin /api)
     v
+-----------------------------+        +------------------------------+
|  FRONTEND  18.140.71.168     |        |  BACKEND  54.254.140.44      |
|  nginx :80                   |        |  Node 20 + pm2 "sfc-backend" |
|  - serves /var/www/sfc-demo  |        |  :3000                       |
|  - /api/  --proxy-------------------> |  --> dev RDS (Postgres :5432)|
|    to 172.26.3.252:3000      |private |  --> S3 bucket-sfc-v3-demo   |
+-----------------------------+ network +------------------------------+
        (public IP)              172.26.x            (public IP + RDS + S3)

Because the SPA calls /api same-origin (proxied), there is no CORS to configure on the browser side and no second public endpoint.

3Prerequisites & access

1

SSH key permissions

chmod 600 /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem
2

Confirm access to both boxes

ssh -i /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem ubuntu@18.140.71.168 hostname
ssh -i /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem ubuntu@54.254.140.44 hostname
If SSH says "Permission denied (publickey)" The .pem was created after the instances, so its public key isn't in authorized_keys. Fix once via the Lightsail console → instance → Connect → "Connect using SSH" (browser terminal, no key needed) and append the public key: 
# get the public key locally:
ssh-keygen -y -f /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem
# paste it into the browser terminal on BOTH boxes:
echo 'ssh-rsa AAAA...sfc-v3-demo' >> ~/.ssh/authorized_keys

4Quick redeploy — do this next time

Once the boxes are set up (they are), a code change only needs these.

Frontend rebuild & ship

Critical — the build flag You must pass VITE_API_BASE_URL=/api. A plain npm run build picks up .env.production which points at the real production API (api.sfcpcsystem.com) and the demo will fail to log in / load data. See Gotcha #3.
cd /Users/mac/dev/sfc-mes-v3/sfcmes-frontend-v3
VITE_API_BASE_URL=/api npm run build
rsync -az --delete \
  -e "ssh -i /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem" \
  dist/ ubuntu@18.140.71.168:/var/www/sfc-demo/
# then hard-refresh the browser (Cmd+Shift+R) to drop the cached bundle

Backend sync & restart

Never overwrite the server's .env The demo .env on the server holds demo-specific values (APP_BASE_URL, ALLOWED_ORIGINS, S3 creds). The --exclude '.env' below preserves it. The server .env is the source of truth.
cd /Users/mac/dev/sfc-mes-v3/sfcmes-backend-v3
rsync -az --delete \
  --exclude node_modules --exclude .git --exclude dist --exclude '.env' \
  -e "ssh -i /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem" \
  ./ ubuntu@54.254.140.44:~/sfcmes-backend-v3/

ssh -i /Users/mac/dev/aws-ssh-sfc-v3-demo/sfc-v3-demo.pem ubuntu@54.254.140.44 \
  'cd ~/sfcmes-backend-v3 && npm ci --omit=dev && pm2 restart sfc-backend --update-env'

5Full backend deploy (fresh box)

1

Install runtime

ssh -i .../sfc-v3-demo.pem ubuntu@54.254.140.44
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs rsync
sudo npm install -g pm2
2

Ship the code

# from your Mac -- first deploy includes .env, then edit it on the server (next step)
rsync -az --exclude node_modules --exclude .git --exclude dist \
  -e "ssh -i .../sfc-v3-demo.pem" ./ ubuntu@54.254.140.44:~/sfcmes-backend-v3/
3

Adjust .env for the demo (on the server)

PORT=3000                              # already correct
APP_BASE_URL=http://18.140.71.168
ALLOWED_ORIGINS=...,http://18.140.71.168 # append the frontend origin
AWS_BUCKET_NAME=bucket-sfc-v3-demo
AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY = demo key   # scoped to the demo bucket
DB_* = dev RDS (unchanged)
4

Install deps, start, persist

cd ~/sfcmes-backend-v3
npm ci --omit=dev
pm2 start src/index.js --name sfc-backend --time
pm2 save
sudo env PATH=$PATH pm2 startup systemd -u ubuntu --hp /home/ubuntu   # survives reboot
Expected log Server running on port 3000 + All necessary tables have been created or already exist. — check with pm2 logs sfc-backend.

6Full frontend deploy (fresh box)

1

Install nginx

ssh -i .../sfc-v3-demo.pem ubuntu@18.140.71.168
sudo apt-get update && sudo apt-get install -y nginx rsync
sudo mkdir -p /var/www/sfc-demo && sudo chown -R ubuntu:ubuntu /var/www/sfc-demo
2

Build & upload

# on your Mac
VITE_API_BASE_URL=/api npm run build
rsync -az --delete -e "ssh -i .../sfc-v3-demo.pem" dist/ ubuntu@18.140.71.168:/var/www/sfc-demo/
3

nginx site config

Write to /etc/nginx/sites-available/sfc-demo, symlink into sites-enabled, remove default:

server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;

    root /var/www/sfc-demo;
    index index.html;
    client_max_body_size 50m;

    # API -> backend over the private network (backend :3000 stays off the public internet)
    location /api/ {
        proxy_pass http://172.26.3.252:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # SPA fallback for React Router
    location / {
        try_files $uri $uri/ /index.html;
    }
}
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/sfc-demo /etc/nginx/sites-enabled/sfc-demo
sudo nginx -t && sudo systemctl reload nginx
Why the private IP? Proxying to 172.26.3.252 (backend private IP) works with no firewall change — same-region Lightsail instances share a private network — and keeps backend :3000 off the public internet entirely.

7S3 bucket setup

The backend serves images as direct public URLs (https://<bucket>.s3.<region>.amazonaws.com/<key>) with no presigning. Therefore the bucket must be public-read, or every image 403s.

Bucket policy (public read)

{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "PublicReadDemo", "Effect": "Allow", "Principal": "*",
    "Action": "s3:GetObject", "Resource": "arn:aws:s3:::bucket-sfc-v3-demo/*"
  }]
}

Also turn off "Block all public access" for the bucket. Then give the demo IAM user write access:

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:PutObject","s3:DeleteObject","s3:GetObject"],
    "Resource": "arn:aws:s3:::bucket-sfc-v3-demo/*"
  }]
}
Existing vs new images Image URLs are stored in the DB at upload time. Old records point at the original sangfahs3 bucket; only new uploads go to bucket-sfc-v3-demo. Both display as long as both buckets stay public-read. Full isolation would require migrating objects + rewriting DB URLs.

8Gotchas & fixes (the reason this doc exists)

#1 — SSH key not authorized on the instances

Symptom: Permission denied (publickey) on both boxes. Cause: the key pair was created after the instances launched. Fix: add the public key via the Lightsail browser-SSH console (see §3).

#2 — Backend crash-loop: Cannot find module './utils/logger'

Cause: the file is Logger.js (capital L) but the code did require('./utils/logger'). Works on macOS (case-insensitive), crashes on Linux (case-sensitive). Fix: corrected the require to ./utils/Logger in src/index.js. Commit this on feature/ai.

#3 — Demo can't log in / no data loads

Cause: vite build loads .env.production, which overrides .env and sets VITE_API_BASE_URL=https://api.sfcpcsystem.com/api (the real production API). The demo bundle then called production instead of /api. Fix: build with a shell override — VITE_API_BASE_URL=/api npm run build (a real env var wins over .env.production in Vite). Hard-refresh the browser after redeploy to drop the cached bundle.

Never point the demo at api.sfcpcsystem.com That is the live production API. The demo must always use /api (same-origin → demo backend).

#4 — Backend firewall

Not needed. Proxying to the backend's private IP avoids exposing :3000 and needs no Lightsail networking rule.

#5 — S3 private bucket → broken images

The app has no presigning, so a fully-private bucket 403s every image. The demo bucket must be public-read (see §7). The original IAM user (sangfahs3.obj-mgmt) is scoped to sangfahs3 only — the demo bucket needs its own key/policy.

#6 — Scanning a piece QR opened nothing

Cause: the in-app drawer QR encoded a bare component UUID, not a URL. Fix: encode ${window.location.origin}/forms/form-component-card/${uuid} in Drawer.jsx so a phone opens the status-update page. Note: QR codes only point at the demo if generated/scanned on the demo site — physical stickers printed from production still point at production.

#7 — QR Save / Print produced a blank image (no QR)

Three separate bugs in QRCodePage.js, all fixed:

BugFix
html2canvas can't capture a live <canvas> → QR blank in outputSnapshot the QR canvas to a data-URL <img> and capture that
Print used window.open() after await → popup blocked (esp. mobile)Print via a hidden <iframe> (never popup-blocked)
Download anchor not in DOM + immediate revokeObjectURL → download cancelledDOM-attach the anchor, defer the revoke

JS=$(curl -s http://18.140.71.168/ | grep -o '/assets/index-[^"]*\.js' | head -1)

# backend health
ssh -i .../sfc-v3-demo.pem ubuntu@54.254.140.44 'pm2 list; pm2 logs sfc-backend --nostream --lines 20'

All HTTP codes should be 200 (a 404 on / at the backend directly is normal — it has no root route).

10Security notes

  • Plain HTTP, no TLS. Logins go in the clear. For a public-facing demo, add a domain + certbot (a bare IP can't get a Let's Encrypt cert).
  • Database is the dev RDS. The demo reads and writes real dev data — deletes/edits during a demo affect it. Consider a snapshot before a customer session, or hide destructive actions.
  • Secrets live only in gitignored .env files (server + local backend). Never put AWS/DB secrets in the frontend .env — it is git-tracked and would be committed. Never commit NOTE.txt-style scratch files with keys.
  • Backend :3000 is not public — reached only via the frontend nginx over the private network.
